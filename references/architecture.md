# AI_UP 架构与关键做法

## 一条任务的流程（app/pipeline.py → Job.run）

```
文案 ──拆句──► 逐句配音（百炼 qwen-audio，按句缓存；每句可带情绪指令 + 语速）
      │                └─► 配音.wav + 每句起止时间 spans
      ▼
数字人混排（avatar_mix.build）：同组素材随机首尾相接，拼得比配音长
      │      ├─ 高清拼接（组内最大分辨率）→ 给“画质还原”当原片
      │      └─ 720p 小拼接 → 送 HeyGem（快、省显存）
      ▼
HeyGem 对口型（clients/heygem.py）→ 画质还原（restore.py）→ 对口型_<key>_高清.mp4
      ▼
字幕.srt（按配音的真实时间生成，不用语音识别）
      ▼
engine/run.py（竖屏、横屏各跑一次）：去停顿 → 编排 timeline.json → 多进程逐帧合成 → 混音 → 编码
      ▼
封面（engine/cover.py，竖屏 + 横屏两张）→ 05_成片/<日期>/
```

缓存：配音按（音色、文字、情绪、语速、模型）缓存；对口型按（配音内容 + 数字人）缓存。所以“重新剪辑”只重跑剪辑和封面。

## 关键做法（都是踩过坑后定下来的）

### 1. 数字人混排，避免倒放
HeyGem 遇到比配音短的素材会“正放-倒放”来回循环，看起来很假。所以先把同组素材随机拼成比配音更长的一条再送进去。
- 换素材的位置落在句子之间的停顿处，看起来像正常剪辑。
- 同一条第二次用到时换一个入点，避免同一个动作重复出现。
- **逐段转码再无损拼接**（concat demuxer）：不要用一个 filter_complex 同时 trim 很多段，高清 HEVC 素材会把内存吃光（Windows 报 WinError 1455 / Cannot allocate memory）。
- **长素材模式**（每条 ≥15 秒且一组总长 ≥120 秒）：每段连续播 10~18 秒，切到另一条的随机位置；切换点写进 `数字人切换点.json`，剪辑时风格的 `pacing.cut_zoom` 在这些点硬切景别（近景 ↔ 中景），像换机位。

### 2. 画质还原（app/restore.py）
HeyGem 会把整张脸重画一遍，眼睛、眼镜、头发都会变糊。做法：
1. 原片按 25fps 解码，与送进 HeyGem 的视频逐帧对应；
2. 用“遮掉嘴部后的小灰度图”把 HeyGem 输出的每一帧对回原片第几帧（Viterbi 平滑，兼容循环和倒放）；
3. 每帧用 YuNet 找嘴角和鼻尖，生成羽化椭圆遮罩，只把遮罩内换成 HeyGem 的嘴，边缘做颜色匹配；
4. 输出原片分辨率（HeyGem 只处理 720p，嘴部放大后贴回 1080p 原片）。原片帧顺序单调时边读边写，不占内存。

### 3. 配音（app/clients/qwen_voice.py）
- 用本人录音的前 20 秒（48k 单声道，不做响度处理）作为高保真参考，注册百炼音色。
- 合成走 qwen-audio TTS，`input.instruction` 传情绪指令（如“用严肃、认真的语气说”），`input.rate` 传语速；接口失败时本地用 atempo 调速兜底。
- 每句单独合成、单独缓存，再按顺序拼接，句间固定留 0.18 秒停顿（`GAP_SEC`）。

### 4. 剪辑引擎（engine/aiclip）
- `planner.build_timeline`：VAD 去停顿 → 时间映射 → 版式分块 → 推镜（关键句推近 / 切换点换景别）→ 画中画素材（关键词优先，通用素材轮播，间隔 ≥8 秒）→ 信息层 / 律师包装 → 音效。
- `compositor.Compositor`：纯 numpy/OpenCV 逐帧合成，所有文字图层预渲染成预乘 alpha，逐帧只做 ROI 混合；多进程分段渲染后拼接。
- 信息层（`hud.py` + `hudplan.py`）：大模型按文案输出 headline/hero/list/cards/stats 信息块和逐句英文字幕；失败时规则版兜底（开场点题、数字放大、步骤列表、结尾总结）。规划结果缓存在工程目录 `信息层规划.json`。
- 律师包装（`law.py`）：顶部金色宋体标题、名牌擦除出场、开场钩子（金字虚焦→清晰、红色大字砸入、打字机）、每句红色重点词弹出、免责声明。重点词只能是原句片段，大模型不许编造法条；规则版只用列点句和法律词表。
- 手动标题（`titlefx.py`）：网页“标题与封面”面板的设置存在 `标题设置.json`，剪辑时通过环境变量 `AICLIP_TITLE_FX` 读入，替换自动的开场 / 顶部标题。
- 封面（`cover.py`）：底图三选一（统一封面照 / 视频挑帧 / 这条单独上传）；视频挑帧按“清晰度 + 脸大小 − 张嘴程度”打分；横屏封面人物放右侧、左侧写字。

### 5. 网页工作台（app/server.py + web/index.html）
- 只用 Python 标准库（http.server），不需要 Node。
- `app/launch.py`：检查依赖、检查端口；发现开着的是旧版本（代码指纹 BUILD 不同）且没有任务在跑，就先关掉旧进程再启动新的。
- 任务队列 `app/jobs.py`：SQLite，单线程依次执行（GPU 一次只跑一个对口型）；每个任务开始前重新载入流程代码。

## 大模型（可选）
`config.local.json` 的 `llm`：`base_url`、`api_key`、`model`、`api_format`（`openai` 走 `/chat/completions`，`anthropic` 走 `/v1/messages`）、`proxy`（`direct` 不走系统代理，或填 `http://127.0.0.1:端口`）。
用途：提炼标题、识别每句情绪、信息层规划和英文字幕、律师包装（标题 / 钩子词 / 重点词）、封面短句。全部失败自动退回规则版，不影响出片。
